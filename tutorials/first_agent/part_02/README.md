# Part 2: Let the Agent Take Another Step

Return a tool result to the model and let it produce an answer.

## Follow the code

1. Read `run_minimal` first. It is the whole agent loop in 15 lines, with no checks.
2. Start with the user question in `history`. Send that history and the tool definition to the model.
3. If the response has no tool call, it is the answer. Otherwise decode the arguments and run the search.
4. Append the response output, including any reasoning items, to history. Append `function_call_output` with the same `call_id` and the real result.
5. Ask the model again. An empty result goes back too; the model decides what to do next.
6. Read `run`. It is the same loop with Part 1's checks and a record of handled call IDs.

## Run from the repository root

```sh
make run-python SERIES=first_agent PART=02
make run-python SERIES=first_agent PART=02 ARGS='--minimal'
make run-python SERIES=first_agent PART=02 ARGS='--trace'
make run-python SERIES=first_agent PART=02 ARGS='--query missing --trace'
make run-python SERIES=first_agent PART=02 ARGS='--max-steps 1'
```

The default demo returns the actual launch note with `reason: final_answer`,
`steps: 2` and `tool_calls: 1`. Its wording is generated by the deterministic
simulation, not by an AI model. `--trace` prints the history the model reads on
each step to stderr. With `--query missing`, the first search is empty, the model
tries `launch`, and the run ends after three steps and two tool calls.
`--max-steps 1` stops with `step_limit`.

## Use a real model

```sh
make run-python SERIES=first_agent PART=02 ARGS='--live'
```

Configure the root `.env` as described in the [series guide](../README.md).
Use `--question 'your question'` to change the live request. `--query` only changes
the simulated model's first search word. Live requests may spend credits.
**Live model verification has not been run.** SDK behavior is tested with HTTP
fixtures; no successful live-model behavior is claimed.
